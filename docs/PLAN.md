## Что будет видно в конце каждого этапа

- Этап 1: репозиторий на GitHub, README и план.
- Этап 2: архитектурный документ, описание api и баз данных.
- Этап 3: `docker compose up --build` поднимает пустые сервисы, CI зелёный, один тест проходит.
- Этап 4: событие `lap_completed` от тестового публикатора доходит до Telemetry, Alerts и Live. Правило срабатывает, алерт приходит через RabbitMQ. Есть отчёт нагрузочного теста.
- Этап 5: те же сценарии работают через браузер.
- Этап 6: проект запускается по README в чистой папке, демонстрация проходит без ручного ввода.

## Риски

- F1 Live Timing неофициальный и может быть недоступен. Не зависеть от него при разработке, работать на сохранённых данных.
- У OpenF1 есть лимиты запросов. Сохранять загруженные данные в базу и не запрашивать их повторно.
- Не хватает времени. Сначала сделать один сквозной сценарий (`lap_completed`), потом остальные типы событий. Нагрузочный тест при задержке перенести на запас (12.11).
