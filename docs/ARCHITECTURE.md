# Архитектура системы

Статус: начальный черновик. Документ будет дополняться по мере разработки.

## 1. Цель и контекст

F1 Monitor показывает ход гонок Формулы 1 в реальном времени и хранит историю прошедших гонок. Во время гонки пользователь видит таблицу, круги, пит-стопы и разрывы и получает уведомления по своим правилам. После гонки данные остаются, и любую гонку можно открыть из списка.

Пользователь один: зарегистрированный посетитель (роль `user`).

## 2. Требования

- Приём потока событий гонки и сохранение в базе.
- Пользовательские правила уведомлений, например: разрыв между пилотами меньше 1 секунды.
- Избранные пилоты, история гонок, сравнение двух пилотов.
- Повторная доставка сообщения не даёт двойного эффекта.
- Уведомление не теряется, если сервис упал при отправке.
- Чужие подписки и избранное недоступны (ответ 403).
- Запуск одной командой `docker compose up --build`.

## 3. Общая схема


Клиент обращается к сервисам через Gateway. Сервисы между собой общаются через RabbitMQ. У каждого сервиса своя база данных.

## 4. Описание сервисов

| Сервис | Ответственность | База данных | Публикует | Читает |
|--------|----------------|-------------|-----------|--------|
| Gateway.Api | Единая точка входа (YARP), маршруты `/api/auth`, `/api/telemetry`, `/api/alerts`, `/livehub` | нет | — | — |
| Auth.Api | Регистрация, вход, выдача JWT | PostgreSQL `authdb` | — | — |
| Telemetry.Api | Хранение событий гонок, список гонок, просмотр гонки, сравнение пилотов | PostgreSQL `telemetrydb` | `import.requested` | `f1.events` |
| Alerts.Api | Правила, подписки, избранные пилоты, журнал уведомлений | PostgreSQL `alertsdb` | `alert.triggered` | `f1.events` |
| Live.Api | SignalR-хаб, текущее состояние гонки, рассылка событий и уведомлений | Redis | — | `f1.events`, `alert.triggered` |
| f1-collector (Python) | Получение данных из F1 Live Timing и OpenF1, публикация событий | нет | `f1.events` | `import.requested` |
| Frontend | Клиент на Vue 3 | нет | — | — |

### Примерные эндпоинты

Список предварительный, точное описание будет в Swagger каждого сервиса.

| Сервис | Запрос | Что делает |
|--------|--------|-----------|
| Auth.Api | `POST /api/auth/register` | Регистрация |
| Auth.Api | `POST /api/auth/login` | Вход, выдача JWT |
| Telemetry.Api | `GET /api/telemetry/races` | Список гонок |
| Telemetry.Api | `GET /api/telemetry/races/{id}` | Данные выбранной гонки |
| Telemetry.Api | `GET /api/telemetry/compare` | Сравнение двух пилотов |
| Alerts.Api | `GET, POST, DELETE /api/alerts/rules` | Правила уведомлений |
| Alerts.Api | `GET, POST, DELETE /api/alerts/favorites` | Избранные пилоты |
| Alerts.Api | `GET /api/alerts/history` | Журнал уведомлений |
| Live.Api | `/livehub` (SignalR) | Подписка на гонку, приём событий и уведомлений |

## 5. Модель данных

Предварительно:
- `authdb`: пользователи (id, email, хеш пароля).
- `telemetrydb`: гонки, события гонок.
- `alertsdb`: правила, избранные пилоты, журнал уведомлений.
- Redis: снимок текущей гонки.

Все события в `f1.events` имеют единый формат, он будет описан в `docs/events.schema.json`.

## 6. Взаимодействие сервисов

Клиент работает с сервисами по HTTP и WebSocket через Gateway. Сервисы между собой общаются через три очереди RabbitMQ:
- `f1.events`: f1-collector публикует, Telemetry, Alerts и Live читают;
- `alert.triggered`: Alerts публикует, Live читает;
- `import.requested`: Telemetry публикует, f1-collector читает.

## 7. Безопасность

- Пароли хранятся как хеш BCrypt, вход выдаёт JWT.
- Роль одна, `user`. Доступ к правилам, подпискам и избранному только у владельца.
- Секреты и строки подключения в переменных окружения, не в репозитории.

## 8. Развёртывание и конфигурация

Вся система запускается через Docker Compose. Порты и переменные окружения будут описаны после создания `docker-compose.yml`.

## 9. Принятые решения

| Решение | Альтернатива | Причина |
|---------|-------------|---------|
| Три отдельные очереди | Одна общая | У каждого сообщения свои читатели |
| f1-collector на Python | на .NET | Есть готовая библиотека FastF1 |
| Одна роль | Несколько ролей | В системе нет нужды в администраторе |

## 10. Ограничения и развитие

- Режима «проиграть гонку заново» нет.
- Live-данные есть только во время гонок, в остальное время можно будет смотреть данные прошедших.
- Возможное развитие: результаты прошлых лет из Jolpica-F1.
